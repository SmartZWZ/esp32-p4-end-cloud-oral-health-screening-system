# 第一阶段：七视图云端对接规范

> 状态：云端实施与硬件对接的冻结协议  
> 云端代码：`D:\Projects\WebProject\齿镜快速部署版`  
> 第一阶段边界：只实现和验证云端，不修改固件，不生成最终七视图综合报告。  
> 安全要求：本文不记录数据库密码、模型密钥、设备令牌或服务端回调密钥。

## 1. 第一阶段目标

在保留现有硬件“原始 JPEG 请求体”上传方式的前提下，实现可独立测试的云端闭环：

1. 验证绑定设备和家庭成员；
2. 创建或识别一次七视图会话；
3. 接收一张候选 JPEG 并临时保存；
4. 调用视觉大模型判断实际区域和拍摄质量；
5. 把模型输出严格归一化为固定 JSON；
6. 对重复 `request_id` 返回相同结果，避免重复调用和重复保存；
7. 提供候选照片确认、丢弃与过期清理；
8. 为后续报告保留 `capture_session_id + region_id` 数据关系。

第一阶段不实现：固件状态机、拍照页下拉框、等待滴声、七张综合报告和端侧模型改造。

## 2. 现有云端基础与缺口

### 2.1 可以复用

当前代码已经具备：

- `/api/process.php` 接收 `Content-Type: image/jpeg` 原始 JPEG；
- 通过 Bearer 或 `X-Device-Token` 验证绑定设备；
- 通过 `X-Member-Id` 验证成员属于设备账户；
- JPEG 类型、大小、宽高和外部存储检查；
- `detections` 正式影像记录；
- AI 牙医调用百炼 OpenAI 兼容视觉接口并要求 JSON；
- 站内图片短期签名 URL；
- 模型调用日志和耗时记录。

### 2.2 必须新增

当前源码没有：

- 七个区域分类和 `wrong_region` 判断；
- 七视图采集会话；
- 临时候选图片；
- `request_id` 幂等和并发去重；
- 确认/丢弃候选图片；
- 面向固件的小型固定 JSON；
- 按会话读取七张图片。

现有 `/api/process.php` 会立即创建正式 `detections`，不适合候选质量检查。第一阶段应新增接口，保持旧上传合同不变。

## 3. 新增接口

| 接口 | 方法 | 请求体 | 作用 |
|---|---|---|---|
| `/api/capture_sessions.php` | `POST` | JSON | 创建或取消七视图会话 |
| `/api/capture_validate.php` | `POST` | 原始 JPEG | 临时保存并返回区域/质量判定 |
| `/api/capture_candidates.php?action=confirm` | `POST` | JSON | 把合格候选图转为正式影像 |
| `/api/capture_candidates.php?action=discard` | `POST` | JSON | 幂等丢弃候选图 |

## 4. 通用规则

### 4.1 HTTPS 与认证

- 只允许 HTTPS；
- 新协议统一使用 `Authorization: Bearer <device_token>`；
- 服务端可继续兼容 `X-Device-Token`；
- 成员必须属于设备绑定账户且为 `active`；
- 固件不能持有模型 API Key、数据库密码或模型服务密钥；
- 日志不得输出令牌、图片正文、内部路径或第三方完整响应。

### 4.2 ID

| 字段 | 要求 |
|---|---|
| `capture_session_id` | 云端生成，不超过 32 个 URL-safe 字符 |
| `request_id` | 板端生成，1～64 字符，仅字母、数字、`-`、`_` |
| `temporary_image_id` | 云端生成，不超过 32 个 URL-safe 字符 |
| `member_id` | 现有成员 `public_id` |

### 4.3 响应

所有响应使用：

```http
Content-Type: application/json; charset=utf-8
Cache-Control: no-store
X-Content-Type-Options: nosniff
```

- 目标响应小于 2 KiB，硬上限 4 KiB；
- 不向板端返回模型原始文本、完整提示词和第三方错误正文；
- 语义上的“照片不合格”仍返回 HTTP 200；只有协议、认证或服务错误才用非 2xx。

## 6. 创建七视图会话

### 6.1 请求

```http
POST /api/capture_sessions.php
Authorization: Bearer <device_token>
Content-Type: application/json
```

```json
{
  "action": "start",
  "member_id": "member_public_id",
  "capture_mode": "seven_view",
  "client_session_nonce": "boot42-0001"
}
```

`(device_id, client_session_nonce)` 必须唯一。网络重试相同 nonce 时返回同一会话。

### 6.2 响应

```json
{
  "ok": true,
  "capture_session_id": "cs_20260812_ab12cd34",
  "capture_mode": "seven_view",
  "member_id": "member_public_id",
  "status": "collecting",
  "current_region_index": 1,
  "expected_region": "front_bite"
}
```

## 7. 候选照片验证

### 7.1 请求格式

```http
POST /api/capture_validate.php
Authorization: Bearer <device_token>
Content-Type: image/jpeg
Accept: application/json
X-Member-Id: member_public_id
X-Capture-Mode: seven_view
X-Capture-Session-Id: cs_20260812_ab12cd34
X-Request-Id: req_boot42_0001
X-Expected-Region: front_bite
X-Region-Index: 1
Content-Length: <jpeg_bytes>

<JPEG 原始字节>
```

单张测试使用：

```http
X-Capture-Mode: single_test
X-Expected-Region: free
```

单张测试可以省略会话 ID 和区域序号。

### 7.2 服务端处理顺序

1. 校验 HTTPS、方法、设备令牌和设备状态；
2. 校验成员归属；
3. 校验请求头长度、枚举和七视图步骤；
4. 以 `(device_id, request_id)` 查询幂等记录；
5. 已完成则直接返回上次的规范化 JSON；处理中则返回 409，不再次调用模型；
6. 限制长度，读取并验证 JPEG；
7. 原子写入网站目录之外的临时目录；
8. 建立候选记录，状态设为 `validating`；
9. 生成短期签名图片 URL并调用视觉模型；
10. 严格解析、白名单化和归一化模型输出；
11. 保存规范化结果、模型名、供应商请求 ID 和耗时；
12. 返回固定 JSON；模型失败不得误判为合格。

## 8. 错误响应

```json
{
  "ok": false,
  "request_id": "req_boot42_0003",
  "error_code": "model_timeout",
  "instruction": "云端检查超时，请重新检查",
  "retryable": true
}
```

| HTTP | `error_code` 示例 | 可重试 | 含义 |
|---:|---|---:|---|
| 400 | `empty_image`、`invalid_request_id` | 否 | 请求格式错误 |
| 401 | `device_unauthorized` | 否 | 设备认证失败 |
| 409 | `request_in_progress`、`region_already_confirmed` | 视情况 | 并发或会话冲突 |
| 413 | `image_too_large` | 否 | 图片过大 |
| 415 | `jpeg_required` | 否 | 非 JPEG |
| 422 | `invalid_region`、`member_invalid`、`session_mismatch` | 否 | 业务参数错误 |
| 429 | `rate_limited` | 是 | 频率过高 |
| 502 | `invalid_model_output` | 是 | 模型输出非法 |
| 503 | `model_unavailable` | 是 | 模型不可用 |
| 504 | `model_timeout` | 是 | 模型超时 |

任何错误都不能推进会话或把候选图标记为接受。

## 9. 确认与丢弃

### 9.1 确认请求

```http
POST /api/capture_candidates.php?action=confirm
Authorization: Bearer <device_token>
Content-Type: application/json
```

```json
{
  "capture_session_id": "cs_20260812_ab12cd34",
  "request_id": "req_boot42_0001",
  "temporary_image_id": "tmp_20260812_a1b2c3d4"
}
```

服务端必须在一个事务中：

1. 验证候选图属于当前设备、成员和会话；
2. 验证 `accepted=true` 且区域尚未确认；
3. 原子移动临时文件到正式历史目录；
4. 创建正式 `detections`；
5. 写入会话与区域关联；
6. 标记候选图为 `confirmed`；
7. 返回正式 `detection_id` 和下一位置。

```json
{
  "ok": true,
  "capture_session_id": "cs_20260812_ab12cd34",
  "temporary_image_id": "tmp_20260812_a1b2c3d4",
  "detection_id": "20260812103000abcd123456",
  "region_id": "front_bite",
  "completed_count": 1,
  "completed_mask": 1,
  "session_status": "collecting",
  "next_region_index": 2,
  "next_region": "left_bite"
}
```

重复确认必须返回同一 `detection_id`，不能重复建档。

### 9.2 丢弃

请求字段相同，action 为 `discard`。操作必须幂等：

```json
{
  "ok": true,
  "temporary_image_id": "tmp_20260812_e5f6a7b8",
  "status": "discarded"
}
```

不合格候选图可以自动进入待清理状态；板端显式丢弃用于尽快释放空间。

## 11. 模型与服务端归一化

模型只做七区域分类、区域匹配和清晰度/曝光/覆盖/遮挡/反光粗判断，不做疾病确诊、毫米级距离估计或综合报告。

模型提示必须包含：七区枚举和解释、左右以被拍摄者为准、当前期望区域、固定 JSON 字段、无法判断时返回 `unknown + region_uncertain + retake`、一次只给一个主要提示。

PHP 必须再次执行：

- 去除可能的 Markdown 包裹并解析 JSON；
- 对所有枚举使用白名单；
- 限制 `instruction` 长度和 `confidence` 范围；
- 缺关键字段时返回 `invalid_model_output`，不能补成合格；
- 七视图中区域不一致时强制 `accepted=false`；
- 任一关键质量项失败时强制 `accepted=false`；
- `accepted=false` 时强制 `decision=retake`；
- 只有数据库确认前六区完成后，第七区才允许 `complete`。

## 12. 临时文件、并发和清理

- 临时文件位于网站代码目录之外，例如现有外部存储根目录的 `capture_tmp`；
- 客户端不能提交文件路径；
- 使用 `.tmp` 写完后原子重命名；
- 默认有效期建议 30 分钟；
- 定时任务清理 `discarded`、`expired` 和失败残留；
- 同一设备同一 `request_id` 只调用一次模型；
- 同一七视图会话同时只允许一个 `validating` 候选；
- 区域未确认时不得上传下一位置；
- 会话取消后不得确认候选图；
- 模型迟到时如果会话已取消，只记日志，不推进状态。

## 14. 第一阶段验收

### 协议与安全

- [ ] 无令牌 401、错误成员 422、非 JPEG 415、超大图 413；
- [ ] 响应不含敏感信息且均小于 4 KiB；
- [ ] 旧 `/api/process.php` 行为未被破坏。

### 七区域与质量

- [ ] 七区各有正确样图并返回预期枚举；
- [ ] 左右互换返回 `wrong_region`；
- [ ] 不确定时返回 `unknown`，不能强行合格；
- [ ] 模糊、暗、过曝、过小、裁切、遮挡、强反光均有固定原因；
- [ ] 每次只返回一个主要提示。

### 生命周期与幂等

- [ ] 同一 `request_id` 不重复调用模型；
- [ ] 重复确认不重复创建 `detections`；
- [ ] 丢弃可重复调用；
- [ ] 不合格图不进入正式档案；
- [ ] 取消后不能确认；过期文件可清理。

### 性能

- [ ] 记录写盘、模型、解析和总耗时；
- [ ] 记录 P50/P95，不直接承诺固定 2～3 秒；
- [ ] 超时、供应商错误和非法输出均返回固定错误 JSON。

## 15. 第一阶段完成条件

满足以下条件后才能开始固件上传服务改造：

1. 接口路径、请求头、枚举和 JSON 字段冻结；
2. 七区域样图完成基础验证，已知不稳定区域有记录；
3. 合格、错误区域、质量错误、模型故障四类结果均可复现；
4. 幂等、确认、丢弃和过期清理通过；
5. 已测得最坏响应长度且不超过 4 KiB；
6. 已记录真实 P50/P95；
7. 不合格候选图不会写入正式 `detections`；
8. 测试记录不包含任何敏感凭据。

第一阶段通过后，固件只按冻结协议实现上传与解析，避免云端字段变化和板端编译、内存问题同时发生。
