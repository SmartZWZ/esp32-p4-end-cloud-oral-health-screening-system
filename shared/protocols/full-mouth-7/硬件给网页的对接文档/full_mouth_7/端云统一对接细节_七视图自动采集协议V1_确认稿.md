# 齿镜端云统一对接细节：七视图自动采集协议 V1（确认稿）

> 适用范围：ESP32-P4 固件、齿镜 PHP 云端、视觉质量复核服务、参考图管理后台、影像档案与口腔综合报告。  
> 文档日期：2026-08-12。  
> 当前状态：字段、枚举、流程和责任边界可按本文开发；参考图模型性能、网络超时和最大响应长度暂不冻结。  
> 安全要求：本文不得填写设备令牌、数据库密码、百炼 API Key 或其他真实密钥。

## 1. 文档目的与优先级

本文用于把硬件端与云端需要共同遵守的细节统一下来，避免双方分别使用不同的模式名称、左右基准、序号、状态和接口语义。

如果本文与以下旧文档冲突，以本文为准：

- `七视图与单张测试采集流程修改方案.md`
- `第一阶段_七视图云端对接规范.md`

本次已经确认的关键变化：

1. 页面文字可以显示“全口七视图（Full Mouth）”，但端云协议值固定为 `seven_view`。
2. 单张模式的协议值固定为 `single_image`，不再使用 `single_test`。
3. 默认模式为 `single_image`。
4. 单张模式由用户每次手动按拍照按钮。
5. 七视图模式只在开始时由用户点击一次“开始采集”；此后由设备自动完成每个区域的播报、倒计时、抓帧、上传、复核和不合格重拍。
6. 七个区域必须全部确认合格，不允许跳过。
7. 设备拍摄得到的 JPEG 已确认存在水平镜像；协议 V1 由云端统一做一次水平翻转，硬件不得自行再翻转上传图。
8. 21 张参考图尚在拍摄，模型阈值、最终超时和响应最大长度等参数待参考图完成后实测。

## 3. 术语和唯一命名

### 3.1 页面名称与协议值

| 页面显示名称 | 协议字段 `capture_mode` | 含义 |
|---|---|---|
| 单张拍摄 | `single_image` | 用户自由拍摄一张；每次由用户手动触发 |
| 全口七视图（Full Mouth） | `seven_view` | 固定七个区域，一次开始后自动推进 |

规则：

- `full_mouth` 只允许作为产品概念或界面英文提示，不作为接口枚举。
- `signal_image` 是早期拼写，不得出现在新代码或数据库中。
- `single_test` 是旧草案值；云端可在过渡期只读兼容，但硬件新代码和数据库统一写 `single_image`。

### 3.2 左右基准

本文中的“左”和“右”始终是**被拍摄者本人的解剖学左右**，不是操作者视角，也不是屏幕画面左右。

例如：

- `left_bite` 表示被拍摄者本人的左侧咬合位；
- 即使未经处理的 JPEG 在云端预览中出现在画面右侧，区域 ID 仍然按被拍摄者本人定义；
- 云端归一化完成后，网页、参考图、模型输入和正式档案都必须按被拍摄者本人的左右理解。

## 4. 七个区域固定定义

七个区域的 ID、序号和顺序一经进入协议 V1 不再调整：

| `region_index` | `region_id` | 中文名称 | 完成位 |
|---:|---|---|---:|
| 1 | `front_bite` | 正面咬合位 | bit 0 / `0x01` |
| 2 | `left_bite` | 左侧咬合位 | bit 1 / `0x02` |
| 3 | `right_bite` | 右侧咬合位 | bit 2 / `0x04` |
| 4 | `upper_left_open` | 张口左上牙区 | bit 3 / `0x08` |
| 5 | `upper_right_open` | 张口右上牙区 | bit 4 / `0x10` |
| 6 | `lower_left_open` | 张口左下牙区 | bit 5 / `0x20` |
| 7 | `lower_right_open` | 张口右下牙区 | bit 6 / `0x40` |

七张完成时：

```text
completed_mask = 0x7F = 127
completed_count = 7
session_status = completed
```

`region_index` 在端云协议和业务上下文中统一使用 `1..7`。如果硬件数组必须使用 `0..6`，请另建变量 `current_region_offset`，不得把数组下标直接作为 `X-Region-Index` 上传。

## 5. 确定后的用户操作流程

### 5.1 单张拍摄 `single_image`

1. 用户选择家庭成员。
2. 模式默认是“单张拍摄”。
3. 用户调整镜头并点击拍照。
4. 硬件抓取当前一帧 JPEG 并按单张旧业务继续保存或分析。
5. 单张模式不强制创建七视图会话，不自动切换区域，不要求集齐七张。

### 5.2 全口七视图 `seven_view`

用户只需要在开始时点击一次“开始采集”。每个区域执行以下固定流程：

1. 设备播报当前区域提示，例如：“牙齿自然咬合，拍摄正面。请对准并保持稳定。”
2. 设备本地播报或显示 `3、2、1`。
3. 倒计时结束时自动抓取当前摄像头帧；不是用户再次按下快门。
4. 设备上传候选 JPEG，并进入“云端检查中”。
5. 云端完成镜像归一化，将候选图与当前区域的三张参考图一并交给视觉模型。
6. 云端返回结构化结果。
7. 如果为拍摄质量不合格：
   - 设备播报一条简短调整提示；
   - 给用户约 2 秒调整时间；
   - 自动重新倒计时并拍摄同一区域；
   - `current_region_index` 不变。
8. 如果候选图合格：
   - 硬件必须调用确认接口；
   - 只有收到确认成功结果后，才标记该区域完成并进入下一区域；
   - 第七张确认成功后完成整个会话。

### 5.3 自动重试与系统错误的边界

以下属于正常质量纠错，可自动重拍当前区域：

- 拍错区域；
- 太远、太近或裁切；
- 偏离中心；
- 模糊；
- 过暗或过曝；
- 强反光；
- 遮挡；
- 无法确认区域；
- 不是有效口腔照片。

以下属于系统错误，禁止无休止自动重试：

- 设备认证失败；
- 家庭成员无效；
- 会话不匹配；
- 网络中断；
- HTTP 响应非法；
- JSON 不完整；
- 模型服务不可用或超时；
- 响应超过硬件安全上限；
- 设备内存分配失败。

发生系统错误时进入 `ERROR` 或 `PAUSED`，由用户选择重试当前区域或取消会话。

## 6. 镜像问题的统一处理

### 6.1 已确认事实

当前 ESP32-P4 摄像头拍摄并上传的 JPEG 是水平镜像的。例如设备实际拍摄被拍摄者右侧牙区，未经处理的云端画面会看起来像左侧。

### 6.2 V1 固定责任

为尽量减少固件改动，协议 V1 固定如下：

- 硬件保持当前摄像头输出，不对上传 JPEG 做翻转；
- `X-Capture-Protocol-Version: 1` 表示设备上传图按“当前硬件镜像输出”处理；
- 云端在临时候选图写入成功后，立即执行一次水平翻转；
- 水平翻转后的图称为“患者坐标规范图”；
- 区域识别、参考图比对、质量判断、正式档案、网页预览和后续报告全部使用患者坐标规范图；
- 原始镜像候选图仅可在临时调试目录短期保留，不进入正式影像记录；
- 云端不得在后续展示或模型调用阶段再次翻转。

数据库或日志至少记录：

```text
source_mirrored = 1
normalization_applied = horizontal_flip
canonical_orientation = patient_coordinate
```

### 6.3 参考图的镜像规则

21 张参考图也必须统一为患者坐标规范图：

- 如果参考图同样由当前 ESP32-P4 拍摄，后台导入后执行一次水平翻转；
- 如果参考图已经被人工翻转或来自非镜像设备，导入后台时必须明确标记来源，不得再翻转；
- 参考图管理后台必须显示“原始方向”和“规范方向”的预览，发布前由管理员确认左右；
- 模型调用时，候选图和三张参考图必须处于相同的患者坐标方向。

### 6.4 禁止事项

- 不批量翻转旧历史图片；旧数据方向问题另做迁移评估。
- 不允许硬件和云端同时翻转。
- 固件未来若改成输出非镜像 JPEG，必须升级协议版本或增加方向能力协商，不能静默改变 V1 行为。
- 网页不得只通过 CSS 镜像掩盖存储方向问题，因为模型读取的仍会是错误方向。

## 7. 端云接口总表

新流程使用独立接口，不修改现有 `/api/process.php` 的合同：

| 接口 | 方法 | 请求体 | 作用 |
|---|---|---|---|
| `/api/capture_sessions.php` | POST | JSON | 创建或取消七视图会话 |
| `/api/capture_validate.php` | POST | 原始 JPEG | 上传候选图并完成区域/质量检查 |
| `/api/capture_candidates.php?action=confirm` | POST | JSON | 把合格候选图转成正式影像 |
| `/api/capture_candidates.php?action=discard` | POST | JSON | 幂等丢弃候选图 |

通用要求：

- 生产环境只使用 `https://wwwxsh.cn`；
- 新协议认证首选 `Authorization: Bearer <device_token>`；
- 云端可继续兼容 `X-Device-Token`，以减少现有固件修改；
- 固件不保存数据库密码和模型 API Key；
- JPEG 作为原始请求体发送，不在板端构造大块 multipart 数据；
- 所有云端响应为 UTF-8 JSON，且不得包含模型原始输出、完整提示词或第三方错误正文。

## 8. 会话接口

### 8.1 创建会话

```http
POST /api/capture_sessions.php
Authorization: Bearer <device_token>
Content-Type: application/json
Accept: application/json
```

```json
{
  "action": "start",
  "protocol_version": 1,
  "member_id": "member_public_id",
  "capture_mode": "seven_view",
  "client_session_nonce": "boot42_s17"
}
```

`client_session_nonce` 由硬件生成。同一设备重试相同 nonce 时，云端必须返回同一 `capture_session_id`，不能重复创建会话。

成功响应：

```json
{
  "ok": true,
  "protocol_version": 1,
  "capture_session_id": "cs_20260812_ab12cd34",
  "capture_mode": "seven_view",
  "member_id": "member_public_id",
  "session_status": "collecting",
  "current_region_index": 1,
  "expected_region": "front_bite",
  "completed_count": 0,
  "completed_mask": 0
}
```

### 8.2 取消会话

```json
{
  "action": "cancel",
  "protocol_version": 1,
  "capture_session_id": "cs_20260812_ab12cd34"
}
```

硬件取消行为优先：停止倒计时和音频、增加 `cancel_generation`、回到空闲页面。云端取消请求可以异步发送，不得因为等待云端响应而阻塞页面退出。

## 9. 候选图验证接口

### 9.1 七视图请求

```http
POST /api/capture_validate.php
Authorization: Bearer <device_token>
Content-Type: image/jpeg
Accept: application/json
X-Member-Id: member_public_id
X-Capture-Mode: seven_view
X-Capture-Protocol-Version: 1
X-Capture-Session-Id: cs_20260812_ab12cd34
X-Request-Id: req_boot42_0001
X-Expected-Region: front_bite
X-Region-Index: 1
Content-Length: <jpeg_bytes>

<JPEG 原始字节>
```

### 9.2 单张请求

```http
X-Capture-Mode: single_image
X-Capture-Protocol-Version: 1
X-Expected-Region: free
```

单张模式可以省略 `X-Capture-Session-Id` 和 `X-Region-Index`。

### 9.3 云端处理顺序

1. 校验 HTTPS、请求方法、设备令牌和设备状态。
2. 校验家庭成员属于当前绑定账户。
3. 校验协议版本、请求头长度和枚举。
4. 用 `(device_id, request_id)` 检查幂等状态。
5. 校验并原子写入原始 JPEG 临时文件。
6. 根据 V1 镜像规则生成患者坐标规范图。
7. 读取当前区域已经发布的 `too_far`、`too_close`、`good` 三张参考图。
8. 把三张参考图和一张候选图交给视觉模型。
9. 对模型输出做严格 JSON 解析、白名单化和业务纠正。
10. 保存规范化结果、参考图版本、模型名和耗时。
11. 返回固定的小型 JSON；不得把模型原始响应转发给硬件。

## 10. 确认与丢弃接口

### 10.1 确认请求

验证响应中的 `accepted=true` 只表示候选图合格，不代表已经正式保存。硬件必须继续调用：

```http
POST /api/capture_candidates.php?action=confirm
Authorization: Bearer <device_token>
Content-Type: application/json
```

```json
{
  "protocol_version": 1,
  "capture_session_id": "cs_20260812_ab12cd34",
  "request_id": "req_boot42_0001",
  "temporary_image_id": "tmp_20260812_a1b2c3d4"
}
```

确认成功响应：

```json
{
  "ok": true,
  "protocol_version": 1,
  "capture_session_id": "cs_20260812_ab12cd34",
  "temporary_image_id": "tmp_20260812_a1b2c3d4",
  "detection_id": "20260812103000abcd123456",
  "region_id": "front_bite",
  "completed_count": 1,
  "completed_mask": 1,
  "session_status": "collecting",
  "next_region_index": 2,
  "next_region": "left_bite"
}
```

第七张确认后必须返回：

```json
{
  "ok": true,
  "completed_count": 7,
  "completed_mask": 127,
  "session_status": "completed",
  "next_region_index": null,
  "next_region": null
}
```

重复确认同一候选图必须返回同一 `detection_id`，不得重复建档。

### 10.2 丢弃请求

```http
POST /api/capture_candidates.php?action=discard
```

请求字段与确认相同。丢弃必须幂等。正常不合格候选图也可由云端自动标记为待清理，不要求硬件必须等待丢弃响应。

## 13. 硬件状态推进规则

### 13.1 启动

```text
IDLE
 -> SESSION_STARTING
 -> GUIDING
 -> ADJUSTING
 -> COUNTDOWN
 -> AUTO_CAPTURING
```

### 13.2 候选图处理

```text
AUTO_CAPTURING
 -> UPLOADING
 -> VALIDATING
```

结果分支：

- `ok=true + accepted=false + decision=retake`：进入 `RETAKE_REQUIRED`，播报提示，约 2 秒后回到 `COUNTDOWN`；
- `ok=true + accepted=true + decision=next/complete`：进入 `CONFIRMING`，调用确认接口；
- `ok=false` 或 HTTP/JSON 错误：进入 `ERROR` 或 `PAUSED`，等待用户操作。

### 13.3 确认成功

- 以确认响应中的 `completed_mask` 更新本地状态；
- `session_status=collecting` 时使用云端返回的 `next_region_index` 和 `next_region`；
- `session_status=completed` 且 `completed_mask=127` 时进入 `SESSION_COMPLETE`；
- 未收到确认成功不得在本地先行递增区域序号。

### 13.4 暂停和取消

七视图采集中保留“暂停”和“取消”：

- 暂停：停止下一次倒计时，不清除当前会话；
- 恢复：从当前未完成区域重新进入引导；
- 取消：立即停止倒计时、等待音和自动抓帧，增加 `cancel_generation`；
- 取消后的迟到响应即使 HTTP 200 也必须丢弃；
- 网络任务不得直接操作 LVGL，统一通过消息队列交给 Presenter。

## 14. 并发、幂等与内存安全

### 14.1 串行原则

- 同一设备同一时刻只允许一个候选图请求；
- 同一七视图会话只允许一个 `validating` 候选；
- 当前区域未确认时不得上传下一位置；
- 不在业务层连续创建七个上传任务；
- ESP32-P4 只保留当前 JPEG，不缓存七张照片；
- 云端负责保存七张照片及其会话关系。

### 14.2 幂等

- `(device_id, request_id)` 唯一；
- 相同 `request_id` 重试返回原结果，不重复调用模型；
- `(device_id, client_session_nonce)` 唯一；
- 重复确认返回原 `detection_id`；
- 重复丢弃返回成功或既有状态。

### 14.3 硬件 RAM 保护

此前语音助手对接已经确认：响应过长可能造成 ESP32-P4 RAM 压力或解析失败。图像质量接口同样必须遵守：

- 服务端只返回本文固定的小型字段；
- 不返回 Base64 图片；
- 不返回模型原始文本、长分析、Markdown 或调试堆栈；
- 硬件响应缓冲优先放 PSRAM 或受控堆内存，不使用大数组占用任务栈；
- 读取响应时必须检查累计长度，超过安全上限立即停止并返回 `response_too_large`；
- 最终缓冲区大小和云端响应硬上限待 21 张参考图完成、真实接口跑通后实测冻结。

旧文档里的“小于 2 KiB、硬上限 4 KiB”目前只视作早期建议，不是本协议的最终验收数值。

## 17. 提示语职责

### 17.1 本地固定提示

区域引导、倒计时、处理中和完成提示优先由硬件本地资源提供，不依赖云端临时生成长语音：

- 当前区域名称和姿势；
- `3、2、1`；
- “正在检查”；
- “当前区域拍摄合格”；
- “七个区域采集完成”；
- 网络错误和重试提示。

### 17.2 云端纠错提示

云端的 `instruction` 只返回一条最主要、可直接播报的短提示，例如：

| `reason_code` | 推荐短提示 |
|---|---|
| `wrong_region` | 请拍摄当前指定区域 |
| `target_too_small` | 请靠近一点 |
| `target_too_close` | 请稍微远离 |
| `target_cropped` | 请远离并拍全牙区 |
| `off_center` | 请将牙区移到画面中央 |
| `blurred` | 请保持摄像头稳定 |
| `too_dark` | 画面较暗，请调整补光 |
| `overexposed` | 画面过亮，请稍微移开补光 |
| `strong_reflection` | 反光较强，请调整角度 |
| `occluded` | 牙区被遮挡，请重新对准 |
| `region_uncertain` | 未识别到目标区域，请重新对准 |
| `not_oral_image` | 未检测到口腔画面 |

硬件可优先按 `reason_code` 播放本地短语，`instruction` 作为兼容显示字段。这样既降低响应长度，也避免云端返回长回答造成设备内存和播报压力。

## 18. 云端数据关系与报告资格

正式图片至少关联：

```text

device_id

capture_mode

region_index
source_mirrored
normalization_applied
reference_set_version

```

七视图会话可生成标准口腔综合报告必须实时满足：

1. `session_status=completed`；
2. 同一账户、同一成员、同一会话；
3. 七个固定区域各有一张有效正式图片；
4. 没有重复区域；
5. 七个图片文件都实际存在且未删除；
6. 所有图片为患者坐标规范方向。

如果用户删除七张中的任意一张：

- 会话标记为 `incomplete`，或至少把 `report_eligible` 设为 false；
- 不允许生成“完整七视图口腔综合报告”；
- 网页明确显示缺少哪个区域；
- 不得用其他时间的图片静默补齐。

“最近最多 6 张照片”继续保留为独立兼容入口，但必须明确它不是规范七视图报告。

## 20. 分阶段对接顺序

### 阶段 A：协议签字

- 双方确认本文字段、枚举、七区顺序、默认模式和镜像责任；
- 硬件端反馈现有命名冲突；
- 冻结接口路径，不改旧 `/api/process.php`。

### 阶段 B：云端模拟接口

- 云端完成会话、验证、确认和丢弃接口；
- 先使用可指定的模拟结果测试 `retake/next/complete`；
- 完成幂等、取消和迟到结果测试；
- 完成镜像归一化单元测试。

### 阶段 C：硬件单张上传联调

- 新接口只上传一张测试 JPEG；
- 验证认证、成员、请求头、JSON 解析和 RAM 使用；
- 网页确认规范图左右方向正确。

### 阶段 D：七视图状态机联调

- 用户只点击一次开始；
- 用模拟结果完成自动倒计时、同区域重拍、确认后推进；
- 测试暂停、取消、迟到响应和确认重试；
- 不接真实参考图模型。

### 阶段 E：21 张参考图后台

- 上传 21 张参考图；
- 确认每张来源方向并生成规范图；
- 完成七区三槽位校验和版本发布；
- 管理员能够替换、预览和归档参考图。

### 阶段 F：真实模型联调

- 每次发送当前区域三张参考图加一张候选图；
- 记录准确率、延迟、响应长度和错误分布；
- 调整提示词、阈值和短提示；
- 冻结第 16 节所有常量。

### 阶段 G：正式档案与报告

- 七张确认图形成会话档案袋；
- 删除图片后实时失去标准报告资格；
- 口腔综合报告读取同一完整会话七张图；
- 旧最近六张入口保留但降级展示。
