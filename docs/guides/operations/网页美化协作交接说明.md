# 齿镜网页美化协作交接说明

> 本说明交给负责网页视觉美化的对话使用。该对话与功能开发对话共享同一项目目录；开始前必须以当前文件夹最新内容为准，不能用旧副本覆盖功能代码。

## 一、当前线上地址与状态

- 正式网页地址：`https://wwwxsh.cn/`
- 原测试地址：`http://8.138.230.100:667/`
- 网页端现在应优先使用 HTTPS 域名；页面美化、链接和展示文本不要再硬编码旧 IP 或 `:667`。
- 宝塔已部署 Let's Encrypt 证书，`wwwxsh.cn` 的 HTTPS 可用。
- 当前站点配置文件：`/www/server/panel/vhost/nginx/8.138.230.100_667.conf`

> ESP32-P4 的旧固件可能尚在使用旧测试地址，硬件迁移由硬件端单独处理；网页美化不应改动硬件接口逻辑。

## 二、本阶段已完成的功能

### 1. 网页端百炼实时语音助手

已增加“助手”页面：

- `assistant.html`
- `assets/css/assistant.css`
- `assets/js/assistant.js`
- `api/assistant.php`
- `ai_gateway/gateway.py`

网页端目前具备：

- 登录用户专属的对话列表和历史消息；
- 新建对话；
- 编辑当前对话标题和助手指令；
- 浏览器麦克风采集；
- 百炼千问实时语音模型的实时转写、文字回复和语音播放；
- 助手消息与用户转写写入数据库。

语音链路：

```text
浏览器 assistant.html
  ↓ HTTPS / WSS
https://wwwxsh.cn/ai-gateway/
  ↓ Nginx 反向代理
127.0.0.1:8765（Python 网关）
  ↓ 服务端保管百炼 API Key
阿里云百炼实时语音模型
```

### 2. AI 助手数据库

已执行迁移并创建：

- `ai_conversations`：按用户隔离的对话及助手指令；
- `ai_messages`：用户/助手消息。

对应 SQL 文件：`database_ai_assistant_migration.sql`。

### 3. 服务器运行环境

旧服务器端 PyTorch/Ultralytics 云端模型环境已停止并删除；模型检测由本地 GPU 工作机处理，不能因为网页美化重新启用或删除相关本地协作接口。

美化工作不得破坏上述业务流程。

## 三、允许美化的范围

可以修改或新增：

- 页面布局、间距、字号、配色、动画和响应式样式；
- `assets/css/*.css` 中的视觉样式；
- 页面文案、图标、非敏感装饰元素；
- `assistant.html` 的视觉层级和组件排版；
- 对话气泡、状态指示、麦克风按钮、空状态、设置弹窗的视觉设计；
- 现有页面的统一导航、主题效果和移动端体验。

建议保持当前黑白、克制、医疗产品感的基础风格，并优先改 CSS。若需调整 HTML，请保留功能节点和脚本顺序。

## 四、严禁修改或删除的内容

### 1. 不修改服务器配置和密钥

禁止触碰、上传、下载、展示或覆盖：

```text
/www/wwwroot/chijing_runtime/ai/bailian.env
/www/wwwroot/chijing_runtime/ai_gateway_venv
/etc/systemd/system/chijing-ai-gateway.service
/www/server/panel/vhost/nginx/8.138.230.100_667.conf
/www/wwwroot/8.138.230.100_667/.user.ini
```

禁止在 HTML、CSS、JS、Markdown、截图、浏览器控制台中写入或输出：

- 百炼 API Key；
- `AI_GATEWAY_SECRET`；
- 数据库密码；
- `MODEL_CALLBACK_SECRET`；
- 设备 `device_secret`、`device_token`。

### 2. 不修改 AI 网关与接口实现

以下文件属于功能和安全边界，网页美化任务不要修改：

```text
api/assistant.php
api/config.php
ai_gateway/gateway.py
ai_gateway/chijing-ai-gateway.service
ai_gateway/requirements.txt
database_ai_assistant_migration.sql
```

也不要改动现有其他 API：

```text
api/auth.php
api/device_link.php
api/devices.php
api/members.php
api/process.php
api/images.php
api/model_jobs.php
api/model_result.php
```

### 3. `app.js` 原则上不修改

`assets/js/app.js` 负责登录态、CSRF、主题、设备、成员、影像管理、预览、模型工具，以及助手页面启动钩子。美化不要重写或覆盖它。

特别必须保留的启动逻辑为：

```js
if (page === 'assistant' && typeof window.setupAssistant === 'function') window.setupAssistant(user);
```

如果确实需要为视觉交互增加 JS，优先新增独立文件，或只在 `assets/js/assistant.js` 中做与助手界面直接相关的、小范围改动，并先验证语音流程。

## 五、助手页面不可破坏的 HTML 约定

`assistant.html` 可以重排样式，但必须保留：

```html
<html data-page="assistant" data-protected="true">
```

必须保留以下元素 ID（`assistant.js` 依赖它们）：

```text
assistant-new
assistant-settings
assistant-conversations
assistant-conversation-title
assistant-status
assistant-http-notice
assistant-messages
assistant-voice-title
assistant-voice-description
assistant-mic
assistant-mic-label
assistant-settings-dialog
assistant-settings-form
assistant-title-input
assistant-instructions-input
assistant-settings-message
assistant-settings-cancel
```

以下 class 也被脚本用作状态/渲染选择器，不得删除或改名：

```text
assistant-console
assistant-conversation
assistant-message
assistant-message-meta
assistant-message-body
```

脚本加载顺序必须保持：

```html
<script src="assets/js/assistant.js"></script>
<script src="assets/js/app.js"></script>
```

不得把它们改成反序、`async` 或 `defer`，否则 `setupAssistant` 可能无法在登录完成后启动。

## 六、其他页面的保护规则

美化其他页面时，保留：

- `<html data-page="..." data-protected="true">`；
- `app.js` 所依赖的现有 `id`、`name`、`data-*` 属性；
- 所有表单的 `method`、接口相关 `action` 或 JS 绑定节点；
- 登录页、注册页、设备、成员、影像页中的 `<script src="assets/js/app.js"></script>`；
- 导航内的 `assistant.html` 入口；
- 图片预览和模型处理弹窗的 `<canvas>`、`img`、缩放控制元素。

不要把业务按钮替换为纯展示元素；例如将 `<button>` 改成无交互的 `<div>` 会使键盘、点击事件和无障碍行为失效。

## 七、域名和地址规则

网页端统一使用：

```text
https://wwwxsh.cn
```

禁止在新的网页代码中加入：

```text
http://8.138.230.100:667
https://wwwxsh.cn:667
```

助手前端通过相对路径访问：

```text
api/assistant.php
/ai-gateway/
```

不要将其改为 IP 或硬编码绝对地址。这样 HTTPS 页面会自动使用同源 `wss://wwwxsh.cn/ai-gateway/`。

## 八、美化完成后的最低验收

在浏览器无痕窗口中完成：

1. 打开 `https://wwwxsh.cn/login.html`，登录成功；
2. 依次打开概览、设备、成员、影像、助手页面，导航正常；
3. 助手页能读取历史记录；
4. 点击“开始”，浏览器可申请麦克风权限；
5. 语音后至少出现用户转写和助手文字回复；
6. 刷新助手页，对话记录仍存在；
7. 影像页能正常预览、缩放、下载和删除图片；
8. 移动端宽度下，导航、弹窗、对话区可用。

若视觉改动造成以上任何功能异常，应先回退本次视觉改动，不应改接口、密钥或服务器配置来“绕过”问题。

## 九、协作要求

1. 每次修改前读取当前文件，确认没有功能对话刚写入的新变更；
2. 优先使用小范围 `apply_patch`，不要用旧压缩包整体覆盖共享目录；
3. 不删除未归属自己的文件；
4. 完成后列出实际修改文件，并至少进行 HTML/JS 静态检查；
5. 如需改动功能文件，先说明原因并等待功能开发对话确认。
