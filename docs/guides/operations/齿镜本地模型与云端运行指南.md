# 齿镜：本地模型与云端运行指南

本文说明“网页/数据库在云服务器，本地电脑 RTX 5060 负责图片检测”的日常使用和恢复方法。

## 1. 当前架构

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 网站、账号、成员、照片、检测记录 | 云服务器 | 对外提供网页、保存数据和模型任务队列 |
| 图片检测模型 | 本机 `D:\chijing_model_agent` | 通过 RTX 5060 自动领取并处理云端任务 |
| 私有网络连接 | Tailscale | 让本机安全访问云服务器，无需开放本机端口 |

云端站点地址：`https://wwwxsh.cn/`。

## 2. 日常检测图片

1. 在网页的图片管理/检测页面选择一张图片。
2. 选择需要使用的模型后，点击“云端检测”。
3. 图片状态会先显示为“等待分析”或“正在分析”。
4. 本机后台工作端会自动领取任务，使用 RTX 5060 运行模型，并把检测结果回传云端。
5. 回到网页刷新或等待页面自动刷新，即可查看检测记录、文字结果和叠加框结果。

正常情况下，不需要再手动执行：

```powershell
cd D:\chijing_model_agent
.\run_worker.ps1 -Once
```

该命令只用于临时测试或手动处理一个任务。

### 当前可选模型

| 网页选项 | 任务标识 | 本地权重 | 输出 |
| --- | --- | --- | --- |
| 龋齿候选检测 | `caries` | `caries_yolov8s_best.pt` | 龋齿候选框 |
| 综合检测 | `both` | `caries_yolov8s_best.pt`、`alphadent_4class_960.pt` | 龋齿、磨耗、充填体、牙冠候选框 |
| 口腔四类分割 | `dental_seg` | `dental_seg_yolo11n_best.pt` | 龋齿、窝洞、裂纹、牙齿的候选框与分割轮廓 |
| 牙结石分割 | `calculus_seg` | `calculus_seg_ensemble_v5.pt` | 牙结石候选区域与分割轮廓 |
| 牙齿轮廓与浅龋暗线 | `tooth_outline` | `tooth_instance_best.pt` | 单牙实例轮廓、轮廓内暗线辅助分析 |
| 全部模型联合分析 | `all_models` | 上述全部权重 | 依次运行五条流水线并汇总结果 |

这些选项都在本机 `D:\chijing_model_agent` 中运行。网页中的“云端分析”表示任务和结果由云端网站管理，不表示 PyTorch 模型运行在云服务器。

四类分割模型权重必须位于：

```text
D:\chijing_model_agent\weights\dental_seg_yolo11n_best.pt
```

更新本地工作端后，需要重启计划任务：

```powershell
Stop-ScheduledTask -TaskName "Chijing Local Model Worker"
Start-ScheduledTask -TaskName "Chijing Local Model Worker"
```

网页要显示第三个模型选项，服务器数据库还必须执行：

```text
database_dental_seg_model_migration.sql
```

## 3. 可视化控制台

桌面已经创建快捷方式：

```text
Chijing Model Console
```

双击后可直接完成以下操作：

- 查看“云端任务 → 下载影像 → GPU 推理 → 回传结果”执行阶段；
- 启动、安全停止或重新启动本地模型后台；
- 查看 RTX GPU 负载、温度和显存占用；
- 核对五个模型权重是否存在；
- 查看结构化运行日志和最近一次任务；
- 执行不会领取任务的只读一键诊断；
- 安装或更新 Windows 登录后自动启动。

也可以在 PowerShell 手动打开：

```powershell
cd D:\chijing_model_agent
.\launch_console.ps1
```

点击窗口右上角关闭按钮时，控制台会收进 Windows 托盘，模型后台不会停止。要退出界面，在托盘图标菜单中选择“退出控制台”。要停止模型后台，必须点击“安全停止”。

如果控制台已经在托盘运行，再次双击桌面快捷方式会直接恢复原窗口，不会重复启动第二个控制台。

控制台不会显示、复制或写入 `config.ps1` 中的模型密钥。一键诊断只会检查密钥是否已配置。

运行状态文件：

```text
D:\chijing_model_agent\runtime\status.json
D:\chijing_model_agent\runtime\events.jsonl
```

云端队列数量需要服务器部署新版文件：

```text
/www/wwwroot/8.138.230.100_667/api/model_jobs.php
```

未部署时不会影响模型任务处理，只会在控制台显示“状态接口待部署”或 `HTTP 404`。

## 4. 本地自动工作端

已配置 Windows 计划任务：`Chijing Local Model Worker`。

它会在登录 Windows 后自动启动并持续检查云端队列；没有任务时不会加载模型，GPU 占用很低。

新版开机任务直接使用 `pythonw.exe` 无终端运行，并在登录后延迟 30 秒启动，给 Windows 网络和 Mihomo/Tailscale 等网络组件预留初始化时间。正常情况下重启电脑后不会再弹出持续输出日志的 PowerShell 窗口。

### 查看是否在运行

在 PowerShell 执行：

```powershell
Get-ScheduledTask -TaskName "Chijing Local Model Worker" | Select-Object TaskName,State
```

输出中的 `State` 为 `Running` 即正常。

### 查看实时日志

```powershell
Get-Content D:\chijing_model_agent\logs\worker.log -Wait
```

停止实时查看时按 `Ctrl + C`。

### 重新启动本地工作端

```powershell
Stop-ScheduledTask -TaskName "Chijing Local Model Worker"
Start-ScheduledTask -TaskName "Chijing Local Model Worker"
```

### 关闭自动运行

```powershell
cd D:\chijing_model_agent
.\uninstall_autostart.ps1
```

如需重新启用：

```powershell
cd D:\chijing_model_agent
.\install_autostart.ps1
```

## 5. 电脑关机、重启或休眠后怎么办

电脑关机、休眠或网络断开时，本机模型和 Tailscale 会暂时离线；云端不会丢失待分析图片。

电脑恢复后按以下顺序处理：

1. 启动电脑并登录 Windows。
2. 等待约 10–30 秒，让 Tailscale 自动恢复连接。
3. 计划任务会自动启动本地模型工作端。
4. 在网页刷新检测记录，等待任务完成。

通常不需要重新登录 Tailscale，也不需要重新安装 CUDA、PyTorch 或模型权重。只有手动在 Tailscale 中退出登录、修改网络账户或删除设备时，才需要重新登录 Tailscale。

若任务在电脑关机前已被领取但未完成，云端会在约 15 分钟后允许本机重新领取该任务。

## 6. 云端连接检查

本地模型工作端现在通过带有效证书的正式域名访问云端：

```text
https://wwwxsh.cn
```

先检查网站接口：

```powershell
curl.exe -sS https://wwwxsh.cn/api/system_status.php
```

返回 `"ok":true` 表示网站、数据库和图片存储正常。

Tailscale 继续保留用于服务器私网维护，但本地模型工作端不再使用旧的
`http://100.70.243.114:667` 地址。服务器启用强制 HTTPS 后，旧地址会被
重定向到 IP 形式的 HTTPS 地址，与 `wwwxsh.cn` 证书不匹配。

### Tailscale 连接检查

优先查看 Windows 右下角托盘中的 Tailscale 图标，确认状态为已连接。

如已安装 Tailscale 命令行，也可在 PowerShell 执行：

```powershell
& "$env:ProgramFiles\Tailscale\tailscale.exe" status
```

本机到云服务器的私网连接测试：

```powershell
Test-NetConnection 100.70.243.114 -Port 667
```

`TcpTestSucceeded : True` 表示本机能通过 Tailscale 到达云服务器，但这
不再是模型工作端访问任务接口的必要条件。

## 7. 模型工作端配置与密钥轮换

本机配置文件：

```text
D:\chijing_model_agent\config.ps1
```

其中包含模型服务密钥。此文件只能保留在本机，**不要上传、不要发送到聊天窗口、不要提交到 Git**。

### 需要轮换密钥时

在云服务器终端执行以下命令。它会生成并写入新密钥，最后仅在服务器终端显示新密钥：

```bash
SITE_ROOT=/www/wwwroot/8.138.230.100_667
NEW_SECRET="$(openssl rand -hex 32)"
sed -i -E "s/(MODEL_CALLBACK_SECRET = ')[^']+(';)/\1${NEW_SECRET}\2/" "$SITE_ROOT/api/config.php"
printf '%s\n' "$NEW_SECRET"
```

复制终端最后显示的新密钥，但不要把它发送给任何人。随后在本机打开：

```text
D:\chijing_model_agent\config.ps1
```

将下面这一行引号中的旧值替换为新密钥并保存：

```powershell
$env:CHIJING_MODEL_SECRET = '新密钥填写在这里'
```

然后重启本地工作端：

```powershell
Stop-ScheduledTask -TaskName "Chijing Local Model Worker"
Start-ScheduledTask -TaskName "Chijing Local Model Worker"
```

如果仅想测试一次，可执行：

```powershell
cd D:\chijing_model_agent
.\run_worker.ps1 -Once
```

## 8. 常见故障排查

### 网页一直显示“等待分析”

依次检查：

1. 本机电脑是否已开机、已登录 Windows。
2. Tailscale 图标是否显示已连接。
3. 计划任务状态是否为 `Running`。
4. 查看 `D:\chijing_model_agent\logs\worker.log` 是否出现报错。
5. 执行 `Test-NetConnection 100.70.243.114 -Port 667` 检查连接。

### 开机后短暂提示 DNS 解析失败

如果电脑使用 Mihomo 的 TUN/Fake-IP 模式，`wwwxsh.cn` 可能会被解析到 `198.18.0.0/15` 范围。开机时模型后台若早于 Mihomo 启动，可能短暂无法解析域名。新版计划任务已延迟 30 秒启动，并采用最长 60 秒的逐步退避重试；网络恢复后会自动回到“等待云端任务”，不需要手工重启。

若错误持续数分钟，可先检查：

```powershell
Resolve-DnsName wwwxsh.cn
curl.exe -I https://wwwxsh.cn/
```

### 日志中出现 401（身份验证失败）

本机 `config.ps1` 中的 `CHIJING_MODEL_SECRET` 与服务器 `api/config.php` 中的密钥不一致。按第 7 节重新同步密钥，然后重启计划任务。

### 日志中出现 SSL 证书域名不匹配

确认 `D:\chijing_model_agent\config.ps1` 使用正式 HTTPS 域名：

```powershell
$env:CHIJING_BASE_URL = 'https://wwwxsh.cn'
$env:CHIJING_HTTP_HOST = ''
```

不要关闭证书验证，也不要使用 `verify=False`。

### 日志中出现 405 Not Allowed

旧版配置通过 Tailscale IP 和 Host 头访问 667 端口。网站启用 HTTPS 后，
该方案会被重定向并导致证书域名不匹配。请改为：

```powershell
$env:CHIJING_BASE_URL = 'https://wwwxsh.cn'
$env:CHIJING_HTTP_HOST = ''
```

### 本机模型服务未启动

运行：

```powershell
cd D:\chijing_model_agent
.\install_autostart.ps1
```

然后再次检查计划任务状态和日志。

### 关闭 PowerShell 窗口后模型后台退出

新版工作进程不再通过 `Tee-Object` 管道运行，并使用隐藏计划任务。请在可视化控制台的“本机设置”中点击“安装 / 更新开机自启”，不要靠一直开着 PowerShell 窗口维持运行。

### 重复点击启动会不会运行两个模型进程

不会。新版 worker 使用 Windows 单实例互斥锁；计划任务也保持 `IgnoreNew`。重复启动会被安全拒绝，避免两个进程同时抢任务和占用双份显存。

## 9. 云服务器注意事项

当前云服务器配置较低，不适合常驻运行 PyTorch/YOLO 模型。云端模型定时任务应保持关闭，由本机 GPU 工作端处理推理。

在服务器终端确认云端模型定时器已停止：

```bash
systemctl disable --now chijing-model-worker.timer
systemctl stop chijing-model-worker.service
```

照片文件存放在云服务器的独立目录：

```text
/www/wwwroot/chijing_storage
```

以后上传网站代码压缩包时，不要覆盖或删除该目录；否则历史图片将无法预览。
