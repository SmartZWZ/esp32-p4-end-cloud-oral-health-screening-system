# 齿镜采集参考图后台部署说明

## 1. 本次功能

- 管理多个参考图版本；
- 每个版本固定 7 个区域 × 3 种距离，共 21 个槽位；
- `draft / published / archived` 生命周期；
- “已发布”和“正在使用”分离；
- 全局质量判断开关；
- 从电脑拖放硬件 JPEG，或从已有设备影像选择；
- 硬件图片保持 ESP32-P4 屏幕显示的左右方向，不在云端翻转；
- 裁剪、任意角度旋转、90°旋转、自动拉直试算和重置；
- 逐张审核、发布前完整性检查；
- 已发布版本复制为新草稿后再修改；
- 操作审计日志；
- 三张参考图加一张候选图的模型测试工具。
- JPEG 上传时移除 EXIF 方向标记，始终以 ESP32-P4 的原始像素方向为准；
- 编辑器支持管理员主动执行左右镜像；
- 已发布版本可以进入修订，替换或编辑错误图片后重新确认、重新发布。
- 质量判断可单独指定视觉模型和最低通过置信度；
- 服务端按区域、距离、清晰度、光照、取景和置信度重新计算是否通过；
- 测试记录支持人工复核，并统计通过结论一致率和距离判断准确率。

## 2. 部署顺序很重要

本次修改为 `detections` 增加了图片方向字段。必须先执行数据库迁移，再覆盖网站代码。否则新代码上线后，ESP32-P4 上传会因为数据库缺少字段而失败。

### 第一步：备份

在宝塔中备份：

- 当前网站目录 `/www/wwwroot/8.138.230.100_667`；
- 当前齿镜 MySQL 数据库。

不要删除：

- `/www/wwwroot/chijing_storage`；
- `/www/wwwroot/chijing_runtime`；
- `/www/wwwroot/8.138.230.100_667/.user.ini`；
- 宝塔 Nginx 站点配置；
- `/www/wwwroot/chijing_runtime/ai/bailian.env`。

### 第二步：执行数据库迁移

如果服务器从未安装过参考图后台，在 phpMyAdmin 中直接导入或执行：

```text
database_reference_library_migration.sql
```

该文件已经包含：

```sql
USE `8_138_230_100_666`;
```

不要切换到 `information_schema`，也不要再次执行 `database.sql`。

随后继续执行：

```text
database_reference_quality_v2_migration.sql
```

如果服务器已经安装并使用参考图后台，只执行 `database_reference_quality_v2_migration.sql`，不要重新执行旧迁移，也不要重新执行 `database.sql`。V2 迁移是幂等迁移，可以重复执行。

### 第三步：确认宝塔 PHP 8.0 图片能力

当前版本不会再用 GD 对设备照片做水平翻转。仍可用下面的命令确认 PHP 图片扩展，供其他图片处理功能使用；即使没有 GD，也不应改变上传照片的左右方向：

```bash
/www/server/php/80/bin/php -m | grep -i '^gd$'
```

正常应输出：

```text
gd
```

如果没有输出：

1. 宝塔 → 软件商店；
2. 找到当前站点使用的 PHP-8.0；
3. 设置 → 安装扩展；
4. 安装 `gd`；
5. 重新启动 PHP-8.0。

不要用系统 `apt install php-gd` 代替宝塔 PHP 扩展，因为网站实际使用的是 `/www/server/php/80/`。

### 第四步：覆盖代码

可以把“齿镜快速部署版”整个代码包解压到：

```text
/www/wwwroot/8.138.230.100_667
```

选择覆盖同名文件，但不要先删除整个网站目录。参考图和家庭影像存储在网站外部的：

```text
/www/wwwroot/chijing_storage
```

正常覆盖代码不会删除这些图片。

### 第五步：服务器语法检查

```bash
SITE_ROOT=/www/wwwroot/8.138.230.100_667

/www/server/php/80/bin/php -l "$SITE_ROOT/api/reference_library_common.php"
/www/server/php/80/bin/php -l "$SITE_ROOT/api/reference_library.php"
/www/server/php/80/bin/php -l "$SITE_ROOT/api/reference_image.php"
/www/server/php/80/bin/php -l "$SITE_ROOT/api/reference_test_image.php"
/www/server/php/80/bin/php -l "$SITE_ROOT/api/process.php"
/www/server/php/80/bin/php -l "$SITE_ROOT/api/images.php"
```

六条命令都应显示：

```text
No syntax errors detected
```

### 第六步：检查接口路由

未登录访问：

```bash
curl -i 'https://wwwxsh.cn/api/reference_library.php?action=bootstrap'
```

预期返回 `401`，并且正文是 JSON：

```json
{"ok":false,"error":"请先登录。"}
```

这表示 Nginx 已正确把新 PHP 文件交给 PHP 处理。若返回 Nginx HTML 404，说明新文件没有上传到正确目录。

### 第七步：网页检查

1. 使用管理员账户登录；
2. 进入“AI牙医”；
3. 打开“AI牙医管理”；
4. 点击“进入参考图管理”；
5. 新建一个草稿版本；
6. 确认页面出现 7 组、每组 3 个槽位；
7. 上传一张明确带左右特征的硬件 JPEG；
8. 打开编辑器，确认云端图片左右方向与 ESP32-P4 屏幕一致；
9. 测试裁剪、旋转、重置和审核。

## 3. 图片保存位置

参考图位于：

```text
/www/wwwroot/chijing_storage/reference_library/<版本编号>/<槽位编号>/baseline.jpg
/www/wwwroot/chijing_storage/reference_library/<版本编号>/<槽位编号>/current.jpg
```

- `baseline.jpg`：首次上传且未做像素镜像翻转的原始基准图；
- `current.jpg`：管理员当前编辑结果；
- 上传时不执行镜像翻转，也不做不必要的二次 JPEG 编码；仅移除可能让浏览器自行翻转画面的 EXIF 方向元数据；
- 点击重置会用 `baseline.jpg` 覆盖 `current.jpg`。

请确认 `.user.ini` 的 `open_basedir` 仍包含：

```text
/www/wwwroot/chijing_storage/
```

## 4. 图片方向规则

代码上线后：

- ESP32-P4 屏幕显示的方向视为正确方向；
- ESP32-P4 通过 `/api/process.php` 上传的新照片按原始 JPEG 字节保存，不做水平翻转；
- 单张保存、单张检测以及旧固件兼容入口都遵循同一规则；
- 管理后台上传参考图时保持上传文件的原始方向；
- 从云端选择设备影像时保持当前已存文件的方向，不再补做翻转；
- 旧历史影像不会被批量自动修改。

## 5. 发布和启用规则

- 从未发布的草稿版本可以上传、替换、编辑和删除；
- 21 张必须全部存在并逐张确认，才允许发布；
- 已发布版本点击替换、从影像选择或编辑时，可以确认进入“修订中”；
- 正在使用的版本进入修订时会自动停止使用并关闭质量判断，防止设备读取修改到一半的参考集；
- 进入修订不会清空全部确认状态，只有实际替换或编辑过的图片会变回“待确认”；
- 修改完成后确认对应图片，点击“确认并重新发布”，然后重新设为当前版本并按需开启质量判断；
- 发布不代表启用；
- 同时最多一个版本正在使用；
- 启用新版本时，旧版本停止使用但保持已发布；
- 当前版本不能直接归档；
- 归档版本先恢复为已发布，才可重新启用；
- 没有当前版本时不能打开质量判断开关。

## 6. 当前阶段边界

参考图后台、版本状态和四图模型测试已经完成。硬件七视图正式质量检查接口仍需等端云协议最终确认后接入，避免硬件对接期间再次修改字段。

在 21 张参考图完成前，不要打开线上采集质量判断。可以先使用已发布但未启用的版本运行后台测试，记录模型响应和延迟。

## 7. 四图质量与延迟测试

测试不要求参考版本已经启用。草稿或已发布版本中，只要所选区域的“太远、太近、合适”三张参考图齐全，就可以运行；归档版本不能产生新测试。

操作步骤：

1. 在参考图后台选中包含 21 张图片的版本；
2. 点击“拍摄质量与延迟测试”；
3. 选择测试图片对应的目标区域；
4. 确认右侧依次出现太远、太近、合适三张参考图；
5. 从云端现有硬件影像中选择候选图，或上传一张 JPEG 测试图片；
6. 点击“发送四张图片并开始计时”；
7. 等待模型返回“可以采纳”或“需要重拍”，并查看操作建议；
8. 查看距离、区域、清晰度、光照、取景和置信度；
9. 查看图片准备、模型响应、结果入库、服务端总计和浏览器端到端往返五段时间；
10. 最近测试会保存在窗口底部，点击任意一条可重新查看该次结果和候选图。
11. 在“人工复核”中选择真实结论并保存；
12. 查看“通过 / 重拍一致率”和“距离判断准确率”，用真实样本评估提示词、模型和门槛。

模型调用至少使用四张图，顺序为：

1. 太远参考图；
2. 太近参考图；
3. 合适参考图；
4. 本次候选图。

对于左/右侧咬合位和四个左/右张口牙列区域，会在第 3 张之后插入相应反侧的“合适”参考图作为区域硬负样本，因此这类请求共五张图，候选图顺延为第 5 张。

质量判断 V3 对左右侧区域增加了反侧硬负样本。比如测试“左侧咬合”时，还会读取同版本“右侧咬合”的合适参考图，要求模型先完成左右区域区分，再判断距离和画质。后台还会把候选图分别与“合适参考图原图”和“合适参考图的水平镜像”做低分辨率像素相似度比较：近似原图时按正例处理，近似水平镜像时按反侧区域拒绝。

咬合侧位不再把张大嘴角、牵拉口角或嘴唇暴露程度作为额外合格条件。管理员确认的“合适”参考图就是构图与暴露范围的最终标准，模型不得发明参考图本身没有满足的新要求。

模型只负责拍摄质量复核，不在这个入口诊断龋齿、牙结石或其他疾病。后台会再次按固定规则计算是否合格，避免模型返回自相矛盾：区域必须匹配、距离必须合适、不能模糊、不能过暗或过曝、取景必须完整，并且置信度达到管理员设置的门槛。任何 `unknown` 都不能通过。

“质量判断模型 ID”留空时跟随 AI 牙医主模型；填写后只影响拍摄质量判断，不影响 AI 牙医。建议先维持 `0.80` 门槛，每个区域分别收集太远、太近、合适样本并完成人工复核，再依据统计结果调整。仅把门槛调高只能减少误通过，不能修复距离分类本身不准的问题。

测试候选图保存在：

```text
/www/wwwroot/chijing_storage/reference_tests/<测试编号>.jpg
```

测试记录保存在 `capture_reference_tests` 表中。本次 V2 升级增加了质量模型配置、置信度门槛和人工复核字段，因此已部署站点必须执行 `database_reference_quality_v2_migration.sql`。
