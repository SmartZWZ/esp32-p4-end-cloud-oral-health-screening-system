# 牙列模型视觉标注部署说明（2026-08-14）

## 1. 本次功能链路

1. 七图档案袋或手动选择的七张照片被保存为牙列生成任务。
2. Windows 本地模型工作端依次处理七个 `tooth_outline` 子任务，提取牙齿候选轮廓和暗线研究候选。
3. 云服务器上的 PHP 后台工作进程逐图调用视觉大模型，完善轮廓并判断 FDI 牙号。
4. 七张图和七份逐图结果再次交给视觉大模型做跨视角统一复核。
5. 用户选择“先确认”时进入人工编辑器；选择“直接生成”时直接绑定到固定 32 颗牙列。
6. 牙列模型不伪造患者三维形态，只负责 32 牙位导航；点击牙齿进入真实多视角单牙档案。

## 2. 部署顺序

### 2.1 先备份

```bash
SITE_ROOT=/www/wwwroot/8.138.230.100_667
cp -a "$SITE_ROOT" "/www/wwwroot/8.138.230.100_667.backup.$(date +%Y%m%d%H%M%S)"
```

不要覆盖或删除 `/www/wwwroot/chijing_storage`、`/www/wwwroot/chijing_runtime` 和数据库。

### 2.2 执行数据库迁移

在 phpMyAdmin 左侧先选中齿镜业务数据库，再导入：

`database_dental_arch_annotation_migration.sql`

不要在 `information_schema` 中执行。全新安装才执行 `database.sql`；现有网站只执行迁移文件。

### 2.3 上传网站文件

可以上传整个“齿镜快速部署版”覆盖站点代码，但必须确认最终文件直接位于站点根目录，而不是多套一层文件夹。

必须确认下列新增文件存在：

- `api/dental_arch_common.php`
- `api/dental_arch_jobs.php`
- `maintenance/dental_arch_worker.php`
- `maintenance/chijing-dental-arch-worker.service`
- `dental-arch-review.html`
- `assets/js/dental-arch-review.js`
- `assets/css/dental-arch-review.css`
- `牙齿轮廓与牙号标注处理指南.md`

### 2.4 安装牙列视觉后台工作进程

```bash
SITE_ROOT=/www/wwwroot/8.138.230.100_667

install -m 644 \
  "$SITE_ROOT/maintenance/chijing-dental-arch-worker.service" \
  /etc/systemd/system/chijing-dental-arch-worker.service

systemctl daemon-reload
systemctl enable --now chijing-dental-arch-worker.service
systemctl status chijing-dental-arch-worker.service --no-pager
```

持续查看日志：

```bash
journalctl -u chijing-dental-arch-worker.service -f
```

该进程只负责调用百炼视觉模型和整理结果，不在 2 核云服务器上运行本地牙齿模型。

### 2.5 确认本地模型工作端常驻

Windows 本地工作端必须保持运行，并能处理 `tooth_outline` 流水线。现有 `D:\chijing_model_agent\worker.py` 已包含该流水线，无需另装一套模型。

### 2.6 配置视觉模型

进入“AI牙医 → 管理后台 → 模型与运行策略”：

- 牙列视觉复核模型：默认 `qwen3.7-plus`
- 牙列备用视觉模型：默认 `qwen3.6-plus`

保存后，新创建的任务使用新配置；已经创建的任务保留创建当时的模型 ID。

## 3. 验证流程

1. 进入成员页面，打开一个完整的七图档案袋。
2. 点击“生成牙列模型”。
3. 页面自动导入七张图；也可以点击单个槽位替换成本地图片。替换后只影响本次自定义输入，不改写原档案袋。
4. 点击“提取轮廓并生成”。
5. 选择“先进入确认页面”。
6. 本地工作端应连续完成 7 个 `tooth_outline` 任务。
7. 云端工作进程随后进行 7 次逐图复核和 1 次七图统一复核。
8. 在确认页面检查牙号、轮廓点和冲突，保存后点击“确认并绑定牙列”。
9. 返回牙列模型：蓝色为可信记录、橙色为待复核、红色为研究候选、白色为本次未记录。
10. 点击任一已记录牙位，确认默认显示“完整图 + 轮廓”。

## 4. 常用排查

数据库迁移未执行时，接口会返回“牙列标注数据库尚未完成迁移”。

本地轮廓长期停在等待状态：检查 Windows 本地工作端是否常驻、Tailscale 是否在线，以及 `tooth_outline` 权重是否存在。

视觉阶段长期不动：

```bash
systemctl is-active chijing-dental-arch-worker.service
journalctl -u chijing-dental-arch-worker.service -n 100 --no-pager
```

任务失败后，网页只重试失败视角的本地轮廓阶段，或只重试视觉复核阶段，不会默认重跑全部七张图。
