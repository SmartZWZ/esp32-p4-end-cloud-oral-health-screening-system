# 设备解绑后历史影像丢失：修复与恢复说明

## 问题原因

旧数据库把 `detections.device_id` 外键设置成：

```sql
ON DELETE CASCADE
```

网页解绑设备时会删除 `devices` 中的旧设备记录，因此 MySQL 会级联删除该设备上传的 `detections` 影像记录。家庭成员本身没有被删除，但成员与历史照片之间的数据库记录已经消失，所以筛选该成员时会显示“还没有影像记录”。

重新绑定会生成新的 `devices.id`，不会自动恢复被旧绑定删除的记录。

## 本次修复

1. 解绑接口删除设备前，先把历史影像的 `device_id` 置空，保留 `user_id` 和 `member_id`。
2. 数据库外键改成 `ON DELETE SET NULL`，避免其他删除路径再次级联删除影像。
3. 提供命令行恢复程序，从外部存储目录中重新登记仍然存在的图片文件。
4. AI牙医页面增加一块固定可见的“一键家庭报告”入口。

## 必须上传

上传并覆盖：

- `api/devices.php`
- `ai-dentist.html`
- `assets/css/ai-dentist-gallery.css`

上传新增文件：

- `database_preserve_images_on_unbind_migration.sql`
- `maintenance/recover_unlinked_device_images.php`

`database.sql` 也已同步更新，但当前数据库不要执行整个 `database.sql`。

## 修改数据库外键

在 phpMyAdmin 左侧选中齿镜业务数据库，只执行：

`database_preserve_images_on_unbind_migration.sql`

执行后，`SHOW CREATE TABLE detections` 中应出现：

```sql
FOREIGN KEY (`device_id`) REFERENCES `devices` (`id`) ON DELETE SET NULL
```

## 恢复已经丢失的影像记录

先在服务器预览，不修改数据库：

```bash
SITE_ROOT=/www/wwwroot/8.138.230.100_667
PHP_BIN=/www/server/php/80/bin/php

"$PHP_BIN" "$SITE_ROOT/maintenance/recover_unlinked_device_images.php"
```

输出的 `[待恢复]` 应显示成员姓名、原日期和图片路径。

确认无误后正式恢复：

```bash
"$PHP_BIN" "$SITE_ROOT/maintenance/recover_unlinked_device_images.php" --apply
```

如果只想恢复一个数据库用户数字 ID：

```bash
"$PHP_BIN" "$SITE_ROOT/maintenance/recover_unlinked_device_images.php" --user=1 --apply
```

恢复程序只处理数据库中已经不存在、但外部存储中仍存在的图片，不会覆盖现有记录。

由于被级联删除的模型结果只存在数据库中，恢复程序只能恢复照片、成员归属、尺寸和原始时间，无法从 JPEG 文件还原过去的模型结果。恢复后的记录会显示为“仅保存”，可以重新发起模型分析。

## 验证

1. 强制刷新浏览器：`Ctrl + F5`。
2. 打开影像管理，选择原成员，确认历史照片重新出现。
3. 打开 AI牙医，标题区下方应出现黑底的“一键家庭报告”入口。
4. 后续再次解绑设备，影像数量不应减少。
